# 05. Actores y roles

Roles de operacion encontrados: ROLE_ADMIN y ROLE_MULTIFUNCIONAL. Ver [enums](../inventarios/enums-estados.md), [rutas](../inventarios/rutas.md) y permisos de endpoints. No se presupone que todos los roles declarados tengan usuarios en BD.

ADMIN puede tener legajo y regimen economico personal, y marcar QR. No se modela como rol distinto para RRHH. `backend/src/main/java/com/policalum/erp/application/service/serviceImpl/NominaServiceImpl.java:309`. MULTIFUNCIONAL muestra QR personal, no escanea ni marca manualmente. `backend/src/main/java/com/policalum/erp/infrastructure/controller/RrhhAsistenciaController.java:158`.

Visitante consume API publica; colaborador externo es dato del servicio, no usuario autenticado demostrado. `backend/src/main/java/com/policalum/erp/application/service/serviceImpl/ServicioServiceImpl.java:153`. ADMIN y MULTIFUNCIONAL no forman una jerarquia de herencia UML. Sistemas externos instalados/activos pendientes de verificar.
